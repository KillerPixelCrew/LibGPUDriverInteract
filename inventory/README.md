# GPU extraction inventory

Snapshot: WSGM 2.1.0, [1df3f4d8987fcff5f1c8f2554c489195f1cb8b13](https://github.com/KillerPixelCrew/WSGM/tree/1df3f4d8987fcff5f1c8f2554c489195f1cb8b13), 2026-10-09.

Preparation only. This repository contains no migrated GPU implementation. Intel and NVIDIA hardware testing was confirmed by the maintainer; AMD was tested by another repository contributor. No runtime or hardware validation ran for this inventory.

The target is a Windows-first .NET LibGPUDriverInteract beside LibHandheld and WindowsDeviceControl. First-party GPU plugins and Device SDK retire after parity. Common Plugin SDK remains for IR and other external plugins.

Driver discovery determines adapter, output, control and value availability. These are source coverage counts, not a fixed supported-hardware list. `driver-discovered` denotes a current implemented path whose availability depends on the installed driver. `current-implementation` denotes an implemented internal/action path. Reserved/unknown entries are separate; every new library backend is still `not-implemented`.

Intel preserves application ownership in `application-profiles.v1.json` and color state in `color.v1.json`. NVIDIA preserves individual native setting ownership in `nvidia-profiles.v1.json`. Corrupt/unreadable journals fail per-application sync without replacing ownership evidence; global controls keep their own independent path. Successful native writes are published without readback gating; uncertain writes are not automatically repeated.

AMD ADLX controls use GPU-wide settings switched by WSGM, with service-wide RSR/AFMF interfaces projected into GPU sections. There is no native Radeon application-profile encoding in this implementation. AMD display controls are GlobalOnly; Intel display controls retain current Switched semantics.

## Native entry points

AMD control tables retain service selector and field vtable slots. ADLX exports use Cdecl; interfaces use Stdcall. IADLXSystem and IADLMapping have no Acquire/Release prefix. Header 2.0.0.125 is negotiated down to the installed runtime version. RSR selector 14 and AFMF selector 17 return service-wide interfaces without a GPU argument. Reference apps and vendor driver DLLs are not copied or redistributed.

NVIDIA uses `nvapi_QueryInterface` from the installed System32 `nvapi64.dll`. Private dithering and HDR output-mode APIs remain optional driver dependencies; missing functions omit their controls. HDR10+ Gaming support is separate from HDR10+ video. Intel uses only present optional IGCL exports, with `ctlInit`, `ctlClose` and `ctlEnumerateDevices` required. Intel also binds [user32 DisplayConfigGetDeviceInfo](https://github.com/KillerPixelCrew/WSGM/blob/1df3f4d8987fcff5f1c8f2554c489195f1cb8b13/src/WSGM.Plugin.IntelGpu/Display/DisplayIdentity.cs#L122) for output identity and [kernel32 GlobalMemoryStatusEx](https://github.com/KillerPixelCrew/WSGM/blob/1df3f4d8987fcff5f1c8f2554c489195f1cb8b13/src/WSGM.Plugin.IntelGpu/Graphics/IntelGraphicsMemoryTransport.cs#L394) for shared-memory eligibility.
